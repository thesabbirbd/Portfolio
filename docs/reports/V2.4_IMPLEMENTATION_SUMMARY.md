# V2.4 Implementation Summary

## Architecture
Transitioned the portfolio to a true Personal Knowledge Engine by integrating a file-based MDX content management system. This architecture requires no external database or CMS, natively extending the existing Next.js App Router. It uses `next-mdx-remote` and `gray-matter` for parsing frontmatter and content, ensuring future scalability for large volumes of notes, journals, and project case studies.

## Routes
Added the following robust dynamic routes and their respective index pages:
- `/notes` and `/notes/[slug]`
- `/journal` and `/journal/[slug]`
- `/projects/[slug]` (dynamically extends the existing `/projects` page)
- `/engineering-lab/[slug]` (dynamically extends the existing `/engineering-lab` page)

## Content System
- **Storage:** Markdown and MDX files stored natively in `content/notes`, `content/journal`, `content/projects`, and `content/lab`.
- **Validation:** Implemented via `src/lib/content.ts` which parses types, slugs, and structured frontmatter (title, description, tags, category, related content fields). Non-published or improperly formatted files gracefully fall back or filter out to avoid breaking the build.

## Components
- `MDXContent.tsx`: Translates markdown elements (headings, code blocks, blockquotes) into responsive, accessible Tailwind components using `@tailwindcss/typography`.
- `ContentCard.tsx`: Reusable, interactive card system designed in the existing glass/spatial aesthetic for listing entries.
- `ContentLayout.tsx`: Premium layout for dynamic routes that includes semantic breadcrumbs, date/category metadata, author attribution, related tags, and semantic spacing tailored for long-form reading without overwhelming visual noise.

## Seed Content
Created 5 genuine, first-hand experience items representing different pillars of knowledge:
1. `content/projects/omnidesk.mdx` — Architectural case study for Omnidesk BD.
2. `content/lab/qwen-automation-limitations.mdx` — Experience running Qwen 0.5B locally for Telegram automation.
3. `content/journal/ubuntu-dev-environment.mdx` — Configuring native Ubuntu for Docker and local AI.
4. `content/notes/openwrt-nas.mdx` — Repurposing a D-Link router into an OpenWrt local NAS.
5. `content/notes/360-photography-maps.mdx` — Observations on contributing to Google Maps as a Local Guide in Rajshahi.

## Structured Data
All generated dynamic routes carry appropriate standard metadata overrides (Title, Description, Canonical URL) matching the exact SEO specifications established in V2.3. The structure leverages Next.js native `generateMetadata()` for dynamic routes.

## Internal Linking & Breadcrumbs
- `ContentLayout.tsx` enforces semantic breadcrumb trails (`Home` -> `Notes` -> `[Article Title]`).
- Future cross-linking supported by `relatedProjects`, `relatedNotes`, and `relatedLab` arrays defined within the MDX frontmatter.

## Sitemap
Integrated dynamic filesystem scanning inside `src/app/sitemap.ts`. Any new Markdown/MDX file pushed to the `content/` directories is automatically parsed and exposed to search engines with correct timestamps and priorities, keeping indexing in sync with development.

## Performance
Article views heavily limit WebGL backgrounds or excessive framer-motion layers. Navigation relies entirely on Next.js `<Link>` prefetching, retaining the site's high Core Web Vitals score. Heavy CSS resets handle markdown styling cleanly.

## Verification
