# V2.4.2 Summary

## Project Architecture
- The existing `/projects` route has been entirely overhauled. It is no longer a static list inherited from the homepage; it is now an interactive `ProjectBrowser` featuring instant client-side categorization, status tags, and technology previews.
- A new dedicated dynamic layout (`ProjectLayout.tsx`) was introduced exclusively for `/projects/[slug]` routes. This allows rendering deep case studies structured around problem context, architecture, failures, trade-offs, and timelines.

## Project Routes
The following project case studies have been dynamically generated and integrated:
- `https://sabbir.nav.bd/projects/omnidesk`
- `https://sabbir.nav.bd/projects/studyos`

## Case Studies
1. **Omnidesk BD:** Evolved from a simple project blurb into a deep architectural overview. The page now explicitly details the usage of Next.js, Node.js, and Redis caching. It also documents a real iteration failure involving client-side vs backend PC builder validation.
2. **StudyOS:** Documents an experimental local AI automation layer. It details the precise trade-off made (latency vs reasoning capacity) and highlights a major failure point regarding 0.5B parameter models hallucinating JSON output during Bash command mapping.

## Evidence
- The `ContentMeta` schema was extended to support:
  - `technologies`: Extracted into a visual tech stack list.
  - `projectStatus`: E.g., active, experimental.
  - `projectRole`: Explaining exactly what was done (e.g., "Lead Developer (Backend & Architecture)").
  - `architecture`: Rendered natively via an `ArchitectureGraph` CSS component, proving relationships between nodes (e.g., FastAPI -> Local Vector DB).
  - `changelog`: A chronological history tracing the project's milestones, complete with dates and summaries.

## Relationships
Both case studies establish a complete contextual loop:
- **Omnidesk BD** links back to the `openwrt-nas` note and the `ubuntu-dev-environment` journal to demonstrate backend/networking crossover.
- **StudyOS** explicitly links back to the `qwen-automation-limitations` lab experiment and the `changing-local-ai-strategy` journal, establishing exactly how one failure drove the architectural pivot.

## UX
- Filters on `/projects` seamlessly toggle between "E-Commerce", "AI & Automation", etc.
- Project cards prioritize immediate legibility over visual noise—limiting listed technologies gracefully with a `+X` counter if the stack gets too large.
- The Case Study layout intelligently removes missing sections, ensuring no awkward "empty states" or fake buttons are present.

## Performance
- Architecture diagrams are built with pure Tailwind CSS HTML nodes and edges. No heavy `d3`, `mermaid`, or `react-flow` dependencies were added to the client bundle.
- The `ProjectBrowser` uses `useMemo` for zero-layout-shift filtering.
