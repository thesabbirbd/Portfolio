## Why Default Dockerfiles Fail Security Audits

Most tutorials teach developers to write Dockerfiles that look like this:

```dockerfile
FROM node:latest
WORKDIR /app
COPY . .
RUN npm install
CMD ["npm", "start"]
```

While functional for quick local testing, deploying this container to a production Kubernetes cluster or Linux VPS creates significant security vulnerabilities:

1. **Root Execution**: By default, processes inside the container run as `UID 0` (root). If an attacker exploits an unpatched library vulnerability (e.g. arbitrary code execution), they inherit root privileges inside the container namespace and can attempt container escape attacks.
2. **Floating Tags**: Using `:latest` means deployments are non-deterministic. A new upstream release can break your build or introduce zero-day CVEs overnight.
3. **Bloated Attack Surface**: Full Ubuntu or Debian images ship with package managers, compilers, and shells (`curl`, `wget`, `bash`) that attackers leverage for post-exploitation pivots.

## 1. The Hardening Checklist

### Rule 1: Always Enforce an Unprivileged User

Create a dedicated system user and switch to it using the `USER` directive:

```dockerfile
# Alpine example
RUN addgroup -S -g 10001 appgroup && \
    adduser -S -u 10001 -G appgroup appuser
USER appuser:appgroup
```

### Rule 2: Multi-Stage Distroless or Alpine Builds

Separate the build dependencies from the final runtime container. Tools like compilers, Git, and package caches should never exist in the production image:

```dockerfile
# Stage 1: Build
FROM node:22-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev

# Stage 2: Runtime
FROM gcr.io/distroless/nodejs22-debian12:nonroot
WORKDIR /app
COPY --from=builder /app/node_modules ./node_modules
COPY --chown=nonroot:nonroot . .
USER nonroot
EXPOSE 3000
CMD ["server.js"]
```

### Rule 3: Add Native Healthchecks

Orchestrators need an internal signal to verify that your process has not entered an unrecoverable deadlock:

```dockerfile
HEALTHCHECK --interval=30s --timeout=5s --start-period=5s --retries=3 \
  CMD ["node", "-e", "fetch('http://localhost:3000/health').then(r => r.ok ? process.exit(0) : process.exit(1))"]
```
