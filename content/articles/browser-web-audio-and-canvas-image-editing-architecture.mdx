## The Shift from Server Processing to In-Browser WASM and Canvas

Historically, rich media editing—such as multi-layer photo cropping, color grading, audio trimming, and dynamic vocal EQ—required round-tripping heavy multi-megabyte payloads to centralized cloud servers running ImageMagick or FFmpeg.

This traditional server-side pipeline introduced three fundamental bottlenecks:
1. **Bandwidth and Latency**: Users had to wait for gigabytes of uploads before previewing a simple crop or contrast adjustment.
2. **Infrastructure Costs**: CPU-heavy image transcoding and audio rendering drove high cloud compute expenses.
3. **Privacy Vulnerabilities**: Sensitive personal photos, voice memos, and unreleased creative drafts resided on remote servers.

With modern browser capabilities—specifically the **HTML5 2D Canvas API**, **Web Audio API (`AudioContext`)**, and **TypedArrays (`Float32Array`, `Uint8ClampedArray`)**—sophisticated media editing can run 100% locally on the user's hardware with sub-millisecond response latency.

## 1. Non-Destructive Canvas Image Editing Architecture

A production-grade image editor must never overwrite the original raw pixels during interactive editing. Instead, it maintains a **declarative transformation state tree** and applies operations through an offscreen render pipeline.

### High-DPI Canvas Rendering

When rendering the workspace canvas on high-resolution displays (e.g. Apple Retina or high-DPI Android screens), naive canvas sizing produces blurry text and pixelated graphics. To maintain crisp fidelity:

```typescript
export function setupHighDpiCanvas(canvas: HTMLCanvasElement, width: number, height: number): CanvasRenderingContext2D | null {
  const dpr = typeof window !== "undefined" ? window.devicePixelRatio || 1 : 1;
  canvas.width = width * dpr;
  canvas.height = height * dpr;
  canvas.style.width = `${width}px`;
  canvas.style.height = `${height}px`;

  const ctx = canvas.getContext("2d");
  if (ctx) {
    ctx.scale(dpr, dpr);
    ctx.imageSmoothingEnabled = true;
    ctx.imageSmoothingQuality = "high";
  }
  return ctx;
}
```

## 2. Web Audio DAW: Waveform Extraction and Parametric EQ

The Web Audio API allows developers to construct modular audio processing graphs using native C++ nodes compiled into the browser engine.

### Decoding and Peak Waveform Extraction

To draw a visual waveform timeline, the audio file is decoded into an `AudioBuffer`. A high-performance loop extracts RMS (Root-Mean-Square) peak envelopes to populate the visual canvas:

```typescript
export function extractWaveformPeaks(buffer: AudioBuffer, numBuckets: number): Float32Array {
  const channelData = buffer.getChannelData(0); // Left/Mono channel
  const bucketSize = Math.floor(channelData.length / numBuckets);
  const peaks = new Float32Array(numBuckets);

  for (let b = 0; b < numBuckets; b++) {
    let sum = 0;
    const start = b * bucketSize;
    const end = Math.min(start + bucketSize, channelData.length);
    for (let i = start; i < end; i++) {
      sum += channelData[i] * channelData[i];
    }
    peaks[b] = Math.sqrt(sum / (end - start));
  }
  return peaks;
}
```

### Implementing 3-Band Parametric EQ and Hum Cutoff

Using `BiquadFilterNode`, audio streams can be filtered in real time before playback or offline export:

1. **High-Pass Filter (`80Hz`, Q: 0.707)**: Cuts out low-frequency microphone plosives, desk thumps, and electrical mains hum without attenuating the fundamental human vocal range.
2. **Peaking Mid EQ (`3.2kHz`, +2.5dB)**: Increases presence and speech intelligibility for podcast and voiceover clarity.
3. **High Shelf (`10kHz`, +1.5dB)**: Adds professional condenser "air" and sparkle to voice tracks.

## 3. Sample-Accurate WAV Binary Encoding in TypeScript

When exporting the final edited audio, the browser generates an authentic RIFF/WAVE header followed by 16-bit signed linear PCM bytes:

```typescript
export function encodeAudioBufferToWav(buffer: AudioBuffer): Uint8Array {
  const numChannels = buffer.numberOfChannels;
  const sampleRate = buffer.sampleRate;
  const numSamples = buffer.length;
  const blockAlign = numChannels * 2; // 16-bit = 2 bytes per sample
  const dataSize = numSamples * blockAlign;
  const out = new Uint8Array(44 + dataSize);
  const view = new DataView(out.buffer);

  // RIFF Chunk Descriptor
  writeAscii(view, 0, "RIFF");
  view.setUint32(4, 36 + dataSize, true);
  writeAscii(view, 8, "WAVE");

  // fmt Sub-chunk
  writeAscii(view, 12, "fmt ");
  view.setUint32(16, 16, true);        // Subchunk1Size (16 for PCM)
  view.setUint16(20, 1, true);         // AudioFormat (1 for PCM)
  view.setUint16(22, numChannels, true);
  view.setUint32(24, sampleRate, true);
  view.setUint32(28, sampleRate * blockAlign, true);
  view.setUint16(32, blockAlign, true);
  view.setUint16(34, 16, true);        // BitsPerSample

  // data Sub-chunk
  writeAscii(view, 36, "data");
  view.setUint32(40, dataSize, true);

  // Write interleaved PCM samples
  let offset = 44;
  for (let i = 0; i < numSamples; i++) {
    for (let ch = 0; ch < numChannels; ch++) {
      const sample = Math.max(-1, Math.min(1, buffer.getChannelData(ch)[i]));
      const intSample = sample < 0 ? sample * 0x8000 : sample * 0x7fff;
      view.setInt16(offset, intSample, true);
      offset += 2;
    }
  }
  return out;
}
```

By keeping audio decoding, transformation, and binary encoding entirely in the client runtime, users enjoy instant exports with zero server compute overhead.
